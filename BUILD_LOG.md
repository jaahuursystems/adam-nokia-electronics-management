- **Speed round (owner report: sign-in/setup very slow, tab changes very slow, no feedback on clicks).** Root causes found in code: each server request re-validated all 30 sheets (~120 Google calls) then read them one by one (~90 calls) — measured 188 calls per read in a call-counting test; the page also blocked on 5–8 separate requests per tab and re-fetched everything after each save; no busy states.
  - Server: schema check once per schema version (Script Property `SCHEMA_OK`); all sheets read in one `batchGet` when the Advanced Sheets service is enabled (manifest), else one call per sheet; new `batch` action (reads only) answers many reads from one load; login/setup and every successful write return the fresh snapshot in the same response. Measured with a fake Sheets: 188 → 59 calls (fallback) → 1 call (advanced service).
  - App: instant tab switching (paint from cache; skeleton if nothing cached; background refresh; repaint only if data changed and the user is not typing); batched reads; priority queue (saves/sign-in go before background reads; refreshes for tabs already left are skipped); automatic retry when the server was only busy; top progress bar; slow-server notice after 7 s; busy buttons ("Please wait…", disabled) on every save and on sign-in/setup; background warm-up of other tabs when idle; session token kept for the day (localStorage) and cached screen shown at once on reopen.
  - **Not measured on real Google yet.** Browser test used the real backend code on a fake sheet with 2.5 s artificial delay per request.
- **UX/bug round (owner: dead sign-in click, sales fail with "apiQ is not defined", wants everything responsive and fast).**
  - **Bug:** `pages1/2/3.js` called `apiQ` (35 places) but never imported it from `APP` → every save (sales, customers, stock, …) threw `apiQ is not defined`. Fixed; scripted check that no other core export is used without being imported.
  - **Stale code:** the service worker was cache-first for app code, so after a release phones kept running the old JS until a second reload (likely why the sign-in click still looked dead). Now network-first for html/js/css/config (cache only as offline fallback; 3.5 s timeout), cache-first for fonts/logos/icons. Cache `ane-shell-v6-*`.
  - **Responsiveness:** pressed/hover/focus effects on all controls, 46 px touch targets and 16 px inputs on phones, `touch-action: manipulation`, haptic tick on Android, page-enter animation, toast icons; any button that triggers a server call gets an automatic spinner + "Please wait…" and repeated taps are ignored.
  - **Tests:** `npm run e2e:flows` (headless Chromium, real backend code on a fake sheet): setup/sign-in, all 13 screens, a POS sale (stock −1, listed in Sales), new customer, no JS errors. Passed at 0 ms and at 1.2 s latency per request.
